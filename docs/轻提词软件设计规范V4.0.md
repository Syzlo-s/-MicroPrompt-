## 1 · 产品概述

轻提词（MicroPrompt）是一款面向 **Windows 10/11** 的轻量级桌面速记软件：单窗口、左右分栏，富文本编辑 + 本地持久化，整体为 **Win11 浅色现代风**，强调流畅过渡与细腻反馈。

自 4.0 起，软件从「纯本地工具」演进为 **本地优先 + 自建账号 + AI 能力** 的智能速记产品：笔记始终在本地（离线可完整使用），账号、AI 润色与会员由自建服务端提供。

### 1.1 核心定位

| 定位 | 说明 |
|---|---|
| 极简操作 | 所见即所得，从新建到保存全程无弹窗打扰 |
| 自动保存 | 输入即存（防抖 + 兜底 + 原子写盘），数据零丢失风险 |
| 沉浸体验 | 启动 / 切换 / 缩放 / 弹层均有成对设计的动画与音效 |
| **本地优先** | 断网不影响本地编辑与保存；笔记默认不上云 |
| 云端可选 | 自建账号服务提供登录、跨设备身份与 AI 额度；服务不可用时给出可读降级提示，不白屏 |

## 2 · 技术栈

### 2.1 客户端与桌面壳

| 层 | 技术 |
|---|---|
| 语言 | TypeScript 5.8 + Rust（stable，本机为 GNU/MinGW 工具链） |
| 桌面壳 | Tauri 2（无边框窗口、原子 JSON 持久化、自定义协议内嵌前端资源） |
| UI 框架 | React 19 + Zustand 5（前端持有全部业务状态，后端只负责读写与窗口控制） |
| 构建 | Vite 7（dev / build）+ `tsc` 类型检查；`scripts/preflight.mjs` 发版前置检查 |
| 富文本 | TipTap 2（ProseMirror）：字号 / 加粗 / 下划线 / 删除线 / 颜色 / 分割线 / 代码引用占位块 |
| 样式 | 单文件 `src/styles.css` + CSS 变量（主题令牌），Win11 浅色现代风 |
| 图标 | SVG 单色（CSS `mask` + `currentColor` 着色） |
| 数据 | JSON：`notes.json` + `refblocks.json`，原子写入（tmp → 校验 → bak → rename） |
| 本地缓存 | `localStorage`（登录态 / 头像 / 主题 / 各项设置） |
| 窗口 | 无边框自绘（`decorations: false`，可缩放，自绘标题栏与窗口按钮） |

### 2.2 服务端（自建，取代第三方账号系统）

| 层 | 技术 |
|---|---|
| 语言 / 依赖 | Python 3 **仅标准库**（单文件 `server_ai/ai_server.py`，目标环境 Python 3.6.8） |
| 进程模型 | 一个进程两个端口：**2580** 账号接口（`/api/*`）+ **2581** AI 与运营后台 |
| HTTP | `ThreadingHTTPServer`，HTTP/1.0 + `Connection: close`（4.1.6 起统一补） |
| 鉴权 | HS256 **自签 JWT**，payload 含 `id` / `name` / `ver` / `exp`；密钥存 `data/jwt_secret.txt`（600） |
| 密码 | `pbkdf2_sha256$迭代数$盐$哈希`（默认 12 万次），比对用 `hmac.compare_digest` |
| 存储 | `data/` 下若干 JSON（用户 / 会员 / 用量 / 订单 / 收款码 / 审计），写入走 tmp + rename 串行化 |
| 备份 | 每次启动自动备份 4 个 JSON 到 `data/backup/`（各留最近 7 份），损坏时自动恢复并留档 `.corrupt` |
| 后台 | 单文件 `admin_ui.html` 注入到 `ai_server.py` 的 `ADMIN_PAGE`（`sync_admin_page.py --check` 防漂移） |

### 2.3 数据位置

| 数据 | 位置 |
|---|---|
| 笔记 / 引用块（默认） | **`<安装目录>\data\`**（4.6.0 起）：安装版 = `D:\轻提词\data\notes.json`；便携版 = exe 同目录 `data\notes.json` |
| 笔记 / 引用块（用户自选） | 用户在「设置 → 存储」里选定的任意目录，记在 `%APPDATA%\<profile>\config.json` 的 `dataDir` |
| 解析优先级 | ① `MICROPROMPT_DATA_DIR` → ② 用户自选位置 → ③ `<安装目录>\data` → ④ 兜底 `%APPDATA%\DesktopNotesDev\DesktopNotes\`（`MICROPROMPT_PROFILE=dev\|test\|stable` 可切，exe 目录不可写时才会用到） |
| 旧数据迁移 | 默认目录里还没有 `notes.json`、而旧位置有 → 首次启动**复制**一份过去（只复制不删除），详见 24.1 |
| WebView2 用户数据 | `%LOCALAPPDATA%\com.microprompt.v4\EBWebView`（**所有副本共用一个**：登录态、界面偏好共享；**不要同时开两个副本**，第二个会因共用同一用户数据目录报 `ERROR_INVALID_STATE`。2026-10-17 核实：代码里按 exe 路径做隔离的那段是死代码，已删除） |

### 2.4 开发规范约束（硬性）

1. 所有动画必须使用**非线性缓动曲线**（OutCubic / InCubic / OutBack 等），禁止生硬跳变；
2. 动画必须成对设计（出现有、消失也有），可中断、不抖动，及时取消 rAF / 定时器；
3. 窗口必须保持**无边框自绘**风格，不启用系统默认标题栏；
4. 新功能界面必须与现有圆角、间距、配色体系保持一致（见第 2 章令牌与第 4 章红线）；
5. 网络能力必须**可离线降级**：断网不得影响本地编辑与保存，失败要给可读提示而不是白屏。

### 3.6 自动保存与登录有效期

- 输入防抖 500ms 落盘；每 2s 检查脏标记兜底补写；写盘串行化；原子写入（tmp → 读回校验 → bak → rename）；
- 保存前清理不再被引用的引用块残留；全程静默保存，**不显示「保存中 / 编辑」状态**；
- 启动先校验登录态：已登录显示主窗口，未登录显示登录页；退出直接关闭；
- 登录有效期 30 天（详见第 18 章「登录有效期」）。

### 3.7 代码引用块

- 把大段代码折叠成一个标题按钮或占位图标，正文保持清爽；点击查看完整代码；
- 添加方式：a) 智能识别（粘贴 / 输入长代码时询问，受「代码块自动识别」开关控制）；b) 手动（选中文本 → 右键「折叠为代码引用块」）；
- 语言识别：自动识别 17 类语言 / 内容并生成标题（html→`body`、css→`box`、js→`login()`、ts→`User`、json→`user`、vue→`.app`、react→`App()`、python→`hello()`、java→`Main`、go→`main()`、rust→`main()`、sql→`users`、shell→`echo`、yaml→`apiVersion`、markdown→`Title`、xml→`root`、text→`代码·N行`）；
- 折叠态以「<标题>」按钮**自适应宽度**内联显示；标题可手动重命名，手动标题不再被自动识别覆盖；
- 展开弹层显示完整代码（含行数），底部提供「还原为文本」「删除」；复制时剪贴板同时写入完整原始代码（`text/plain` + `text/html`）；
- 持久化：原文存 `refblocks`（键 = uuid），笔记 HTML 内只留占位 `<span data-refblock="uuid">　</span>`；详见第 14 章。

## 4 · 视觉风格红线（新增 / 修改功能必须遵守）

> 前 9 条沿用 V3.0；第 10 ~ 13 条是 4.1.8 踩坑后补的（都是"曾经做错过"的地方）。

1. 风格基调为 **Win11 浅色现代风**，深色仅作为可选主题色；
2. 动画必须使用**非线性缓动曲线**，禁止生硬跳变；
3. 禁止大面积高斯模糊；局部柔化用遮罩渐隐；
4. 禁止紫色系正文（主题色可选紫罗兰，但不用于正文）；
5. 所有按钮必须有 hover / press 动画反馈；
6. 图标必须是 SVG 单色可着色，禁止位图拉伸模糊；
7. 新功能界面必须与现有圆角、间距、配色体系保持一致；
8. 数据写入必须经过原子保存链路，保证零丢失；
9. 网络能力必须可离线降级，登录 / 保存不得依赖网络才能用；
10. **颜色一律走主题变量**：禁止在组件里写死 `#fff` / `#d1d9e6` 之类的高光与投影色（换主题、开护眼模式时必须自动跟随）；
11. **开关 / 分段开关 / 滑块的轨道要"平"**：用 `--c-track` 平轨道 + 滑块下投影表达深度，禁止再用写死的白 / 灰**拟物 inset 阴影** —— 那圈灰和卡片边框并排就是一条硬分界（详见 4.11 与第 10 章）；
12. **二级页面用分组卡片**：页面底色压成 `--c-window`（`#f8fafc`），卡片白底 + 1px `#e8edf5` 描边 + 极淡投影；卡片内行与行用 1px `--c-border` 分隔；
13. **破坏性 / 不可逆操作必须二次确认**：删除笔记、退出登录、修改密码等一律走确认弹窗或二级界面，且确认按钮文案要写清后果。

## 9 · SVG 图标设计规范

### 9.1 基准尺寸（硬性要求）

| 项目 | 要求 |
|---|---|
| 校验尺寸 | 16 / 32 / 64 px |
| 渲染原理 | SVG 矢量源，运行时超采样渲染 → 包围盒归一化 → 按需缩放居中 |
| 设计要求 | 16px 最小档仍清晰可辨、不断线、不糊 |

### 9.2 技术硬性要求（违反将导致渲染错误）

1. viewBox 必须为 0 0 24 24（统一 24 网格设计画布）
2. 优先【单 path + 单色 fill】，禁止多 path 双色图标
3. 禁止使用 stroke 描边（着色器只替换 fill，stroke 会残留原色）
4. 基准色统一 fill="#25314C"（运行期替换为主题色）
5. 内容主体四周留白 ≥ 2px（相对 24 网格），禁止顶满画布
6. 文件保存为 SVG 1.1，无外部引用/滤镜，英文小写命名

### 9.3 视觉硬性要求

1. 视觉线宽 1.5~2px（24 网格），保证 16px 下仍 ≥1px、不断线
2. 外轮廓圆角 1~2px，禁止尖锐直角
3. 图形居中、光学平衡
4. 语义明确，一眼可辨

### 9.4 现有图标体系

- `app-logo`、`close`、`maximize`、`minimize`、`pen`、`pin`、`restore`、`chuangjian`、`shanchu`、`font-size`、`format-brush`、`bold`、`underline`、`strikethrough`、`divider`、`palette`、`arrow-down`、`code` 等

## 14 · 代码引用块规范

### 14.1 功能背景与目标

本软件常被用于记录给 AI 使用的长提示词（含 outerHTML 等大段代码）。此类内容占版面大、阅读打断感强。引用块功能将其折叠为一个微型图标或标题按钮，使正文保持清爽，点击即可查看完整代码。

### 14.2 交互流程

- 添加方式（两种）：
  - 智能识别：粘贴/输入包含长代码特征（≥3 行且含 `< { [ function SELECT const` 等）的文本时，弹出询问「是否折叠为引用块？」；该行为受设置项「代码块自动识别」控制
  - 手动添加：选中目标文本 → 右键菜单「折叠为代码引用块」
- 折叠后效果：正文中保留一个占位按钮，显示自动识别的标题
- 展开查看：单击 → 弹层显示完整代码（含行数统计），底部提供「还原为文本」「删除」操作
- 还原为文本：撤销折叠，把代码原文恢复为普通文字，并清除数据
- 删除：移除占位与代码原文（保存时孤儿清理兜底）
- 引用样式：浅灰底 + 深蓝代码角标（`</>`），带 hover 高亮与 press 反馈

### 14.3 视觉与动效规范

- 折叠态：内联自适应宽度按钮，显示「<标题>」
- 默认状态：浅灰底 `#EEF0F5` + 深蓝图标 `#25314C`

## 15 · 登录与账号系统规范

### 15.1 账号体系总览（服务端是唯一真源）

账号一律由**自建账号服务**提供（2580 端口，`server_ai/ai_server.py`），客户端里不写死任何账号：

| 项 | 约定 |
| --- | --- |
| 身份来源 | 服务端 `data/users.json`（UUID 主键 + 用户名唯一） |
| 登录令牌 | 服务端自签 HS256 JWT（payload `id / name / ver / exp`），存 `microprompt.authToken` |
| 凭证版本 | JWT 里的 `ver` = 账号 `tokenVer`；改密 / 停用 / 踢下线都会 +1，旧令牌立刻失效 |
| 注册 | `POST /api/signup`（用户名 1~32 位，可用中英文 / 数字 / `_` / `-`；密码 ≥8 位） |
| 登录 | `POST /api/login/oauth/access_token` |
| 读资料 | `GET /api/get-account`（只读；`id/name/displayName/avatar/createdTime/lastLoginTime`） |
| 改昵称 / 头像 | `POST /api/update-user` / `POST /api/upload-resource` |
| 改密码 | `POST /api/change-password`（必须验原密码；成功后换发新令牌，其它设备掉线） |

- ⛔ **已废弃（4.0.3 起移除）**：内置离线管理员（`local-admin`）、本机离线账号（`local:` 前缀 /
  `microprompt.localAccounts`）。启动时若发现这类旧登录态会直接清除并要求重新登录（`src/services/localAuth.ts`）。
- 未连接服务端时：登录 / 注册提示「无法连接服务器，请检查网络或服务器地址」；
  **已登录用户的本地编辑与保存完全不受影响**。

### 15.6 登录态门禁

- 启动时校验登录态（restoreAuth）：
  - 本地有令牌且 30 天有效期内 → 直接放行（不请求后端，避免网络波动误登出）

- 登录态存 localStorage（键见 10.3）

## 20 · 服务端规范（账号 · AI · 运营后台）

> 服务端是**唯一判定点**：额度、会员、订单、权限全部在服务端算，客户端只负责展示与引导（改前端、清缓存都绕不过）。

### 20.1 端口与职责

| 端口 | 职责 | 说明 |
|---|---|---|
| **2580** | 账号接口 `/api/*` | 注册 / 登录 / 读资料 / 改资料 / 上传头像 / **用户自助改密** |
| **2581** | AI 与运营后台 | `/ai/*`（润色、额度、订单）+ `/admin`（电脑端控制台） |

同一个进程、同一份 `data/`；账号接口与 AI 接口共用一套 JWT 身份。

### 20.2 账号接口（客户端只调这几个）

| 接口 | 用途 | 关键约定 |
|---|---|---|
| `POST /api/signup` | 注册 | 用户名 1~32 位，可用中英文 / 数字 / `_` / `-`（首尾不能是 `_` `-`）；密码 ≥8 位 |
| `POST /api/login/oauth/access_token` | 登录 | `x-www-form-urlencoded`；返回 `{access_token, expires_in, token_type}` |
| `GET /api/get-account` | 读资料 | `Authorization: Bearer <token>`；只返回 `id/name/displayName/avatar/createdTime/lastLoginTime` |
| `POST /api/update-user` | 改昵称 / 头像 | 忽略请求体里的 `id/name/pwd/tokenVer/status/note`（客户端改不了自己的身份与状态） |
| `POST /api/upload-resource` | 上传头像 | multipart；按**文件头魔数**判类型、≤2 MB、服务端生成文件名 |
| `POST /api/change-password` | **自己改密码（4.1.8 起）** | 见 20.4 |

- **令牌**：HS256 自签 JWT，payload 含 `id / name / ver / exp`，`ver` = 账号的 `tokenVer`；密钥在 `data/jwt_secret.txt`（600 权限，首次启动自动生成）。
- **错误话术**（客户端直接显示）：`用户名或密码不正确` / `该账号已被停用，请联系客服` / `尝试次数过多，请 10 分钟后再试` / `用户名已被注册` / `请求格式不正确`。
- **未知的 `/api/*`、`/avatar/*`** 一律 404 JSON；所有响应都带 `Access-Control-Allow-Origin: *`，`OPTIONS` 预检返回 204（否则 WebView2 会把它当网络故障）。
- **防爆破**：同名 + 同 IP 双维度限速；登录失败一样计数。

### 20.3 令牌与「踢下线」机制

- 每个账号有一个 `tokenVer`（凭证版本）；**改密 / 停用 / 踢下线**都会让它 +1；
- 校验时 `int(data["ver"]) != int(acc["tokenVer"])` 直接判 401 —— 旧令牌即使没过期也立刻失效；
- 登录成功时用**当前** `tokenVer` 重签令牌，所以改完密码的本机用服务端补发的新令牌继续用。

### 20.4 用户自助改密（4.1.8）

| 规则 | 为什么 |
|---|---|
| 必须带登录令牌，**身份只从令牌取** | 不接受客户端传 `uid` / `username`，否则等于「拿自己的令牌改别人的密码」 |
| **必须验原密码** | 手机 / 电脑被同事临时借用时，不能直接就把密码改掉 |
| 新密码 8~128 位、不能与原密码相同 | 与注册同一套规则，避免「改了个更弱的」 |
| 失败话术统一 `原密码不正确` | 账号枚举防护，与登录一致 |
| 成功后 `tokenVer + 1` | 其它设备上的旧令牌立刻失效（顺手踢下线） |
| **同时返回一张新令牌** | 当前设备换票后继续用，**改完不用重新登录** |

客户端表现：设置 → 用户 → 账号安全 → 「修改」弹出**二级界面**（原密码 / 新密码 / 确认 + 显示密码按钮），
成功提示「密码已修改：其它设备上的登录已失效，本机继续保持登录」。

### 20.5 AI 与订单接口（2581）

| 接口 | 说明 |
|---|---|
| `POST /ai/polish` | 鉴权 + 计次 → 调 DeepSeek → `{result, quota}` |
| `GET/POST /ai/quota` | 当前额度 / 会员状态（客户端用 POST：旧服务端对 GET 会回不带 CORS 头的 501，无法区分「服务端旧版」与「连不上」） |
| `POST /ai/order` | `{plan: day\|month}` → 生成订单 |
| `GET /ai/order?id=` | 订单状态（客户端轮询） |
| `POST /ai/orders/mine` | 我最近一笔订单（重开弹窗恢复状态用） |
| `POST /ai/order/claim` | 用户点「我已完成支付」 |
| `GET /ai/paycodes` | 可用收款码清单（按套餐 × 支付方式） |
| `GET /ai/paycode/<套餐>/<方式>.png` | 收款码图片（管理员在线上传） |
| `POST /ai/pay/notify` | 预留：支付通道回调（自动开通） |
| `POST /ai/admin/orders` · `/confirm` · `/reject` · `/grant` · `/users` · `/overview` · `/logs` · `/account/*` · `/paycode/*` | 运营后台接口，全部要 `X-Admin-Key` |

- **错误码**：`401 auth` / `402 free_exhausted`·`member_cap` / `429 rate_limited` / `403 admin_auth` / `404 not_found` / `501 pay_channel_off`。
- **数据文件**（`data/`）：`users.json`、`members.json`、`usage.json`、`orders.json`、`admin_key.txt`、`jwt_secret.txt`、`paycode/`、审计日志 JSON；写入走 tmp + rename，单进程锁串行。
- **订单状态机**：`pending`（待付款）→ `claimed`（用户点了已完成支付）→ `paid`（管理员确认，开通会员）；
  另有 `canceled`（**打回**：没收到款 → 作废，不开会员、不计收入、留审计，用户可重新下单）。
- **防重复收款**：同一用户 + 同一套餐只允许一笔 pending（10 分钟内重复下单复用同一订单号；超 10 分钟自动把旧的置 `canceled`）；管理员 confirm 幂等（重复确认只加一次天数）；已被 `paid` 的订单不允许打回。

### 20.6 运营后台（`/admin`，电脑端控制台）

- 页面源文件是 `server_ai/admin_ui.html`，由 `sync_admin_page.py` 注入到 `ai_server.py` 的 `ADMIN_PAGE`（**线上只传一个 ai_server.py**）；`--check` 比对是否忘了注入。
- 六个页签：概览（KPI + 趋势图 + 额度分布）/ 用户与额度 / 订单 / 收款码 / 操作日志与安全 / 设置。
- **数据变了页面 2 秒内自己刷新**（轻量轮询，只有数据变化才重绘）；读接口失败自动重试一次并给可读提示，写接口绝不重试。
- 配色与客户端同一套令牌（单一强调色 + 灰阶描边，无渐变）；明暗两套配色；窄屏下导航改为顶部横排。
- 后台可对账号**重置密码 / 停用 / 启用 / 踢下线 / 备注**；订单可**确认收款开通**或**打回（未收到付款）**；收款码可在线上传。

### 20.7 部署与运维

```bash
# 本机 → 服务器（先传成 .new，比对 md5 后再切换）
scp server_ai/ai_server.py admin@<服务器>:/home/admin/ai_server/ai_server.py.new
scp server_ai/selfcheck.py admin@<服务器>:/home/admin/ai_server/selfcheck.py.new
# 服务器
cd /home/admin/ai_server
md5sum ai_server.py.new                      # 与本机比对
python3 -m py_compile ai_server.py.new       # 语法检查
cp ai_server.py ai_server.py.bak-<版本>-$(date +%Y%m%d-%H%M%S)   # 留回滚点
mv ai_server.py.new ai_server.py && mv selfcheck.py.new selfcheck.py
./start.sh && sleep 3 && python3 selfcheck.py
```

- `start.sh` 会 `pkill -f "[a]i_server.py"`、加载 `run.env`、再 `nohup python3 ai_server.py > ai_server.log 2>&1 &`；
- **必需环境变量**：`MP_DEEPSEEK_KEY`（缺失直接拒绝启动）、`MP_ADMIN_KEY`、`MP_AUTH_MODE=builtin`；可选 `MP_DATA_DIR`、`MP_PBKDF2_ITERS`、`MP_RATE_LIMIT_SEC`；
- **自检** `python3 selfcheck.py`：版本 / 套餐 / 鉴权 / 假 token / 账号兼容层 / CORS，全 `[OK]` 才算生效；
- **回归**：`tests/test_rules.py`（62 项）、`tests/test_accounts.py`（85 项）、`tests/admin_panel_smoke.mjs`（95 项，真浏览器点后台）—— 全程 `MP_MOCK=1`，不花钱、不碰真实数据；
- **回滚**：换回 `ai_server.py.bak-*` 再 `./start.sh`；线上保留 4.1.4 以来的每个回滚点；
- **备份**：每次启动自动备份 4 个 JSON 到 `data/backup/`（各留 7 份），损坏时自动恢复并把坏文件留档 `.corrupt`。

## 21 · AI 润色功能规范

### 21.1 功能概述

对用户写的提示词做 AI 润色 / 规范化，结果生成在**原文下方**，不覆盖原文。AI 结果固定格式：

```
第一行：标题（末尾全角冒号，如「AI润色功能的修改：」）

正文（结构清晰，必要时用 1、2、3 编号）
```

DeepSeek Key 只存服务器，客户端不暴露。

### 21.2 服务架构

- 链路：客户端 → 自建 AI 中转（阿里云 2581）→ DeepSeek API；
- 中转程序 `server_ai/ai_server.py`（Python3，标准库）；接口 `POST /ai/polish {text, system?} → {result}`；
- 模型 `deepseek-chat`，`temperature 0.3`；请求超时 60s。

### 21.3 客户端交互

- **入口一（自动）**：设置 → AI 助手 → 开启「自动润色」后，输入停顿约 1.2s 自动出现「AI 润色」按钮；
- **入口二（手动）**：选中文字 → 右键菜单「AI 润色」（始终可用）；
- **识别范围**：自动按钮识别从开头到结尾的完整提示词（所有正文段落），自动排除 AI 方框；右键优先润色选中内容，选区丢失时退回整篇；
- **插入位置**：润色内容所在**整段的下方**（先定位段落结束位置），绝不插入到用户文字中间；
- **结果呈现**：只读方框（不可编辑、不可选中），完成后方框下方自动新增空段落供继续编辑。

### 21.4 视觉与动效

- 按钮：简洁浅色（白底 + 主题色描边 / 文字）小圆角胶囊；左对齐最后一段文字、跟随编辑区滚动；渐入渐出（opacity / transform 0.28s OutCubic）；
- 方框：圆角 12px；边框为固定细线（约 1px，主题色），无霓虹；
- 生成动画：逐段生成（每段约 60~90ms）→ 生成中文字模糊（`blur 3px`，仅文字、边框清晰）→ 完成后自上部逐行向下变清晰（每行错开约 0.14s、单行过渡 1.1s）→ 每行进入带非线性位移（0.4s `cubic-bezier(0.22,1,0.36,1)`）。

### 21.5 数据与安全

- DeepSeek Key 只在服务器；失败时方框内显示「AI 润色失败：原因」；
- 服务端支持请求内可选 `system` 覆盖系统提示词（默认含标题格式规范）；
- **只发送用户选中的文本**，绝不发送整篇笔记或其它笔记。

### 21.6 失败与边界（4.1.3 ~ 4.1.8 陆续补齐）

- **超长预检**：单次上限 2 万字符（与服务端一致）。「自动润色」默认润色整篇，长笔记容易超限 —— 客户端**先本地拦截**并提示「选中内容 N 字，超过单次上限 20000 字：请分段选中后再润色」，不发请求、不插入方框（服务端拒绝时同样不扣额度）；
- **失败不留痕**：调用失败时**删除占位方框**，只在顶部提示（额度不足还会自动弹开通窗）—— 方框是「结果容器」，失败原因不该被永久写进用户笔记，更不该存进 `notes.json`；
- **额度可见**：按钮悬浮说明显示额度（免费版「今日剩余 N/3 次」、会员「今日已用 N/300 次」）；服务端连不上但本地有缓存额度时，额外提示「暂时连不上 AI 服务，上面显示的是上次获取到的额度」。

## 22 · AI 额度与付费会员

### 22.1 规则总览（额度以服务端为准）

| 用户 | 规则 |
|---|---|
| 未付费 | 每天 **3 次** AI 润色（北京时间 0 点重置） |
| 会员 | 不限量；防滥用上限 **300 次/天** |

| 身份 | 必须带登录令牌（4.1.0 起为自建 JWT；离线 / 未登录不可用 AI） |

- 判定点唯一（服务端）；客户端只做展示与引导；
- 付费只影响 AI 功能，基础编辑与保存不受任何影响。

### 22.2 开通流程（半自动收款）

选套餐 → 生成订单（展示订单号 / 金额 / 收款码）→ 扫码付款（可备注订单号后 4 位）→ 点「我已完成支付」→
客户端每 4 秒轮询订单状态 → 管理员确认后自动显示「开通成功」并刷新额度。

- 收款码按「套餐 × 支付方式」展示（微信 / 支付宝切换；某张缺失退回通用 `paycode.png`，全无则提示「收款码未上传 + 客服邮箱」）；
- **防重复付款**：中途关掉弹窗再打开会恢复原来那笔订单的状态（等待确认 / 继续付款），不会让用户再付一次；
- **弹窗自适应**：面板高度上限 520px 并随窗口等比缩放；付款页内容更高时，「重新选套餐 / 我已完成支付」做成**吸底操作栏**，任何窗口尺寸下主按钮都可见。

### 22.3 管理员确认收款（两条路）

| 方式 | 说明 |
|---|---|
| A. 运营后台（推荐，手机可用） | 浏览器打开 `http://<服务器>:2581/admin` → 粘贴管理员密钥（只存该浏览器）→ 订单页点「确认收款并开通」；同页支持加天数、查额度、2 秒自动刷新 |
| B. 服务器命令行 | `python3 admin_cli.py list` / `python3 admin_cli.py confirm <订单号>` |

- **没收到钱 → 点「打回（未收到款）」**：订单置 `canceled`、不开会员、不计收入、写审计，用户可重新下单；
- 已 `paid` 的订单不允许打回（防止一键抹掉会员）；
- 以后接支付通道：在 `ai_server.py` 的 `_do_pay_notify()` 里验签 → 取订单号 → 调 `store.confirm_order()`，回调地址 `/ai/pay/notify`；**客户端无需改动**（订单状态是轮询来的）。

### 22.4 界面规范

- 设置 → AI 助手：顶部「AI 会员」卡片显示到期时间（或今日剩余次数）、剩余天数、刷新、开通 / 续费按钮；
- 额度用尽 / 达到上限：方框内写明原因 + 顶部提示，并自动弹出「开通 AI 会员」窗口（无需用户自己找入口）；
- 一级菜单「AI 助手」在未开通时带一个**浅琥珀小圆点**（4.1.4 起由橙色「会员」标签改成圆点，悬停才出文字说明）。

## 23 · 版本管理与构建发版规范

### 23.1 两条版本线的现状

- **客户端与服务端各有一条版本线**，但 4.5.0 起**同号发布**（4.1.2~4.1.7 期间只发服务端，客户端停在 4.1.1）；
- 客户端版本号必须**六处一致**（`npm run preflight` 会一次性核对）：

| # | 位置 |
|---|---|
| 1 | `package.json` |
| 2 | `src-tauri/tauri.conf.json` |
| 3 | `src-tauri/Cargo.toml`（`Cargo.lock` 由 cargo 自动更新） |
| 4 | `src-tauri/inno/setup.iss`（`MyAppVersion` + `OutputBaseFilename`） |
| 5 | `src/components/SettingsDialog.tsx`（关于页） |
| 6 | `src/components/WelcomeScreen.tsx`（欢迎页） |

- 服务端版本是 `server_ai/ai_server.py` 里的 `VERSION` 常量（`/ai/health` 上报）；preflight 只要求它**不落后于客户端**；
- `package-lock.json` 的版本也随客户端一起改（避免 lock 停在旧版本号）。

### 23.2 目录与产物的关系

| 位置 | 角色 |
|---|---|
| `轻提词V4.0\`（源码仓库） | **唯一真源**：`src/` 前端 + `src-tauri/` Rust + `server_ai/` 服务端；改 bug 只改这里 |
| `轻提词V4.0\release\轻提词.exe` | 最新构建的**便携版**（+ `WebView2Loader.dll`） |
| `轻提词V4.0\release\installer\` | 各版本安装包 + 便携版存档（回滚点） |
| `便携版\` | 唯一一份免安装副本（`轻提词.exe` + `WebView2Loader.dll` + `data\`）：给别人试、U 盘带走、临时测试都用它；笔记在 `便携版\data\`，与安装版互不影响 |
| `便携版\旧数据_2026-10-17\` | 2026-10-17 合并「开发版 / 稳定版」时归档的两套历史笔记（8 条 + 6 条），留着可随时用「设置 → 存储」切过去看 |
| `D:\轻提词\` | **正式安装的**副本（开始菜单 → 轻提词），普通用户用这个 |
| `历史归档\` | 旧快照（`.bak-*` exe、旧安装包、旧便携 zip、旧版规范）；**比赛提交材料永远不动** |

> 2026-10-17 起**取消「开发版 / 稳定版」两份副本**：它们本来就是同一个 exe（SHA256 相同）的两份拷贝，
> 反而让人分不清"哪个才是我的笔记"。4.6.0 的笔记默认跟着 exe 目录走，
> 想同时保留两套数据就在「设置 → 存储」里改位置，不必再复制 exe。

### 23.3 构建流程

```powershell
cd D:\Desktop\桌面速记\轻提词V4.0
npm run preflight                                  # 1) 前置检查：.env 凭据 + 6 处版本号 + 打包文件 + 线上版本
npm run build                                      # 2) 前端（tsc + vite build，版本串先进 dist）
$env:CARGO_TARGET_DIR = 'D:\mp4target'             # 3) Rust：必须用纯 ASCII 目录（见 23.4）
cd src-tauri; cargo build --release --features tauri/custom-protocol
# 4) 产物回填：D:\mp4target\release\microprompt-v4.exe + WebView2Loader.dll
#    → 复制成 release\轻提词.exe，并同步到 便携版\
```

### 23.4 打包（发布固定走 Inno Setup）

```powershell
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" src-tauri\inno\setup.iss
# 产物：release\installer\轻提词安装包_v<版本>.exe（约 3.3 MB）
# 交付：复制一份到工作区根目录，并配一个「双击安装_轻提词<版本>.bat」
```

- `setup.iss` 必须保存为 **UTF-8 with BOM**（否则中文应用名 / 输出文件名乱码，preflight 会检查）；
  ⚠️ 用编辑器改这个文件时要确认 BOM 没被吞掉（`edit` 类工具可能把 BOM 去掉，preflight 的 `[3]` 段会报）；
- 安装包从 `D:\mp4target\release\` 取 `microprompt-v4.exe` 与 `WebView2Loader.dll`，并打入 `src-tauri\resources\*`；
- `DefaultGroupName={#MyAppName}`：开始菜单出现在「轻提词」文件夹里（否则会落进「(Default)」）；
- **4.6.0 起**：`DefaultDirName=D:\轻提词` + `DisableDirPage=no`（让用户能改安装位置）、
  `[Dirs]` 建 `{app}\data` 且 `uninsneveruninstall`（卸载不删笔记）、`[Code] InitializeWizard` 在 D 盘不存在时回退到 `{autopf}` 并说明笔记位置。详见 24.7。

**两个坑（都踩过）**

| 坑 | 现象 | 处置 |
|---|---|---|
| 中文路径 | `dlltool: Can't create .lib file: ...\rustcXXXX\kernel32.dll_imports.lib: No such file or directory`（路径变乱码） | 本机是 GNU/MinGW 工具链，`dlltool` 按 ANSI 代码页读参数、处理不了中文路径；把编译中间产物放纯英文目录（`CARGO_TARGET_DIR`）即可 |
| NSIS 路线不可靠 | `npm run tauri build` 能出包、大小版本都对，但**静默安装什么都不装、手动双击报「无法打开要写入的文件」** | 发布不用 NSIS，固定 Inno（4.1.8 实测：同一时刻 4.0.3 / 4.1.1 的老包都能装、4.1.8 的包不能，根因未查到） |

### 23.5 发版清单（每条都要过）

1. `npm run preflight` 全绿（凭据 / 6 处版本号 / setup.iss BOM / 线上服务端版本）；
2. `npm run build` + `cargo build --release --features tauri/custom-protocol` 无错误；
3. **服务端先上线**（新客户端要调新接口时，顺序不能反：先发客户端会 404）；部署后 `selfcheck.py` 全 `[OK]`；
4. 服务端回归：`tests/test_rules.py`、`tests/test_accounts.py`、`tests/admin_panel_smoke.mjs` 全过；
5. `ISCC.exe src-tauri\inno\setup.iss` 出安装包；
6. **`node scripts/verify-installer.mjs` 必须 9/9**（真机：装 → 验版本 → 启动验界面 → 卸载 → 还原注册表与快捷方式）。
   **这一条是硬门槛** —— 它正是 4.1.8 那次漏掉的步骤，漏了就会发出一个"文件大小和版本号都对、但装不上"的包；
   （4.7.0 起脚本会**按字节备份并还原**桌面 / 开始菜单的「轻提词」快捷方式：测试安装与正式安装共用同一个
   AppId、`{autodesktop}\轻提词.lnk` 是同一个路径，它卸载时会连用户原来那份一起删掉）
7. **4.7.0 起多一步：生成在线升级清单并上传** —— `node scripts/make-update-manifest.mjs --notes-file release\notes-<版本>.md`
   （算 size + SHA-256、写 `server_ai/updates/latest.json`、把安装包与便携版复制进 `updates/files/`），
   再把整个 `server_ai/updates/` 目录 scp 到服务端 `ai_server.py` 同级；上传后
   `curl -s http://<服务器>:2581/updates/latest.json` 与 `curl -sI .../files/<文件名>` 都要通。
   **顺序**：先把清单与文件放上服务器，再对外说"可以升级了"（清单没到 = 老客户端查不到，只是静默跳过）；
8. 人工装一次到 `D:\轻提词`（或用户指定目录），确认版本号与界面；
   4.6.0 起还要顺手核对：默认安装位置是 `D:\轻提词`、装完有 `data\` 目录、卸载后 `data\` 还在；
9. 同步 `release\轻提词.exe`、`便携版\`（覆盖前先备份成 `轻提词.exe.bak-<旧版本>`，旧快照进 `历史归档\`）；
   2026-10-17 起**不再有「开发版 / 稳定版」两份副本**，发版只同步这一处 + 安装包；
10. 提交 + 推送（细粒度提交：服务端 / 客户端 / 测试 / 文档 / 发版各一个），并在比赛材料里补部署提醒；
11. 交付物：工作区根目录一份 `轻提词安装包_v<版本>.exe` + `双击安装_轻提词<版本>.bat`。

### 23.6 给用户装新版的正确姿势

- **双击 `双击安装_轻提词<版本>.bat`**（由系统自带 cmd 拉起安装包，SmartScreen 不拦）；
- 或直接双击安装包，弹「Windows 已保护你的电脑」时点「**更多信息 → 仍要运行**」；
- 装完从开始菜单「轻提词」启动；旧版本的便携版仍留在 `release\installer\` 里可回滚。

## 24 · 存储位置与文件管理台（4.6.0 新增）

> 4.6.0 解决两件事：**笔记存在哪由用户决定**，以及**笔记多了以后怎么高效地管**。
> 4.8.0 起，随手翻的入口由「向上展开的气泡卡片抽屉」改为**右侧笔记侧栏**（第 26 章）；
> 管理台继续作为**叠加能力**存在，两者共用同一份 store；**4.8.3 起管理台改为从侧栏展开铺满工作区的卡片墙**
> （左侧分类保留，右侧与侧栏同一套卡片，只是列数更多），不再是三栏弹窗。

### 24.1 数据位置的解析顺序

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 环境变量 `MICROPROMPT_DATA_DIR` | 开发 / 排障用，指定后忽略一切配置 |
| 2 | 用户在「设置 → 存储」里选的位置 | 记在 `%APPDATA%\<profile>\config.json` 的 `dataDir` |
| 3 | **默认：`<安装目录>\data`** | 安装版 = `D:\轻提词\data`；便携版 = exe 同目录 `data\` |
| 4 | 兜底：`%APPDATA%\DesktopNotesDev\DesktopNotes` | exe 目录不可写（如装进 `Program Files`）时使用 |

- 目录可用性判定要**真实写一个探测文件**（`dir_writable`），不能只看目录是否存在；
- 旧数据自动迁移：默认目录里没有 `notes.json`、而旧位置有 → 首次启动**复制**一份过去
  （只复制、不删除，旧文件原样留作备份；已迁移过就不再重复）；
- `config.json` 只存位置（`{"dataDir": null}` = 用默认），不存笔记内容；
  选回默认位置时把 `dataDir` 清成 `null`（而不是写死一个绝对路径，避免换安装目录后失效）。

### 24.2 存储页（设置 → 存储）

- 入口：设置面板一级菜单「存储」（数据库图标），副标题「笔记保存位置、备份与文件管理」；
- 卡片内容：当前路径（带「复制」）、`N 条笔记 / M 个数据文件 / 共 X KB`、
  「打开文件夹」「更改位置」「恢复默认」「文件管理」四个按钮、当前目录的文件清单（名称 / 大小 / 修改时间）；
- 检测到旧位置还有数据（`legacy_has_data`）时给一条提示条，一键搬过来；
- 「打开文件夹」用 `explorer.exe` 打开当前笔记目录，并且**选中 `notes.json`**（`/select,`）；
- 同一套控件（`StorageControls`）有 `card` / `bar` 两种形态：设置页用卡片；4.8.3 起管理台底部那条存储细条已随三栏一起删除，`bar` 形态暂无入口（样式与 `StoragePanel` 保留）。

### 24.3 更改位置（三步走，笔记不能丢）

1. **先 flush**：把内存里未落盘的改动强制写盘，再走下一步；
2. **复制 + 读回校验**：把 `notes.json` / `refblocks.json` 复制到目标目录，然后**读回来解析**
   —— 必须解析成合法笔记 JSON 才算成功；目标目录已有 `notes.json` 时先备份成
   `notes.json.<时间戳>.bak`（**只增不覆盖**）；
3. **最后才写配置**：校验通过才写 `config.json`。任何一步失败都保持原位置不变，并给出可读错误。

- 二次确认弹窗三个选项：**取消 / 只切换（不搬文件） / 移动并切换**（默认高亮第三个，破坏性操作必须确认）；
- 切完立即重新读取数据并刷新列表；原本打开的笔记若还在就保持选中，不在了就选最近修改的一条；
- 「恢复默认」走同一条链路，只是目标 = `<安装目录>\data`。

### 24.4 文件夹选择器（自绘，不用系统弹窗）

- 为什么自绘：Tauri 官方 `dialog` 插件不在本项目依赖里（离线构建环境拉不到 crate），
  而且系统弹窗与本软件的浅色自绘风格不搭；
- 结构：左侧快捷位置（桌面 / 文档 / 下载 / 软件数据目录 / 各盘符）+ 顶部面包屑 + 中间子文件夹列表 + 底部按钮；
- 能力：进子目录、返回上一级、跨盘符跳转、**就地新建文件夹**、实时显示最终路径；
- 键盘：`Enter` = 确认，`Esc` = 取消；只用现有色板与缓动曲线，不引入新令牌。

### 24.5 文件管理台（Ctrl + K）

> 侧栏负责「随手翻」，管理台负责「一次看很多」。两者共用同一份 store 与同一张 `NoteCard`，
> 任一处改完另一处立刻同步。**4.8.3 起管理台不再是三栏弹窗**：只保留左侧分类，右侧整面都是
> 和侧栏一样的卡片墙（铺满后自动加列）；**4.8.4 起它是一整页** —— 盖住整个窗口（包括顶栏区域），
> 顶栏只留头像与置顶 / 最小化 / 最大化 / 关闭，中间的笔记名隐藏，所以看不到软件首页的标题与分界线。

- 打开方式：① 主界面 `Ctrl / Cmd + K`；② 笔记侧栏底部「管理」按钮；③ 设置 → 存储 → 「文件管理」；
- 形态：`.fm-layer` 在 `.workspace` 内 `inset: 0`（**不再让开 42px**，`z-index: 70`），`.fm-shell`
  用 `padding-top: 42px` 把内容让到顶栏下方，但自己的渐变背景铺满整页；顶栏在管理台打开时被抬到
  `z-index: 90`（`.app-root.manager-open`），保留头像与窗口按钮，`.titlebar-center` 设为不可见；
- **连续展开动画（4.8.5 重做）**：外层不再做整层淡入、也不再动画 `width`（会挤压内容、产生「刷新」感），
  改为 `.fm-shell` 的 `clip-path` 揭示：首帧 `inset(0 0 0 calc(100% - var(--notes-sidebar-w)))` 正好等于
  侧栏占据的那块区域，420ms `cubic-bezier(.22,1,.36,1)` 展开到 `inset(0)`；外壳背景与侧栏同一渐变
  （`#FDFDFF → #F8FAFD`）且始终不透明，所以全程不会闪白；收起用 `fm-retract` 反向收回（300ms）。
  面板内容再延迟 50ms 做 260ms 轻淡入；卡片本身仍走 4.8.4 的 FLIP —— 打开瞬间读取侧栏里可见卡片位置，
  管理台里同一批卡片先被摆回侧栏位置，再用 480ms 滑到各自新格子（侧栏没露出的卡片按 `--card-i` 错峰淡入）；
  侧栏关闭时 `--fm-from-w` 取 `0px`，即从右边缘展开；
- 布局：左侧**保留**分类导航 `.fm-rail`（168px，样式未改，展开时从左侧滑入；4.8.7 起分组见下）；
  右侧 `.fm-main` = 精简头部 + 卡片墙 + 底部悬浮工具栏；
- 头部：当前分类名 + 「命中 / 总数」胶囊 + 搜索框 + 关闭（×）；不再有排序下拉、新建主按钮、存储细条；
- 卡片墙：`.ns-grid.fm-wall`，`repeat(auto-fill, minmax(138px, 1fr))` —— 默认 1096 窗口 5 列，
  侧栏只有 2 列，所以一屏能看到的笔记明显更多；卡片复用 `NoteCard`，与侧栏完全一致
  （4.8.4 起两行标题、同款悬停滑动操作块）；
- 左栏分类（4.8.7 重排，带实时计数，固定三组）：
  【全部笔记】全部 / 置顶 / 今天；【按颜色】黑色 / 蓝色 / 红色（顺序按用户指定，
  `data-filter` 依次是 `c0` / `c2` / `c1`）；【我的合集】未分类合集 / 各用户合集 / ＋新建分类合集。
  4.8.7 起「按时间」的「最近 7 天 / 更早」与左栏的「灰度提示词」入口移除
  （灰度从顶部「合集」抽屉进入，见 26.11）；
- **合集（4.8.5）**：左栏最上方、在「全部笔记」分组之前是 `.fm-rail-collections`「合集」入口（主题色淡底，
  比普通项更突出）。点开是**手机应用抽屉式**的文件夹总览 `.fm-collections`：文件夹网格
  `repeat(auto-fill, minmax(132px,1fr))`，每张 `.fm-folder` 有文件夹图标 / 名称 / 条数，
  「灰度提示词」额外带「自动」药丸，末尾是「＋ 新建分类」卡。点任意文件夹 = 进入按该分类过滤的卡片墙，
  头部出现「‹ 合集」（`.fm-back`）返回；两向动画成对（进入 260ms 淡入上浮 / 返回 240ms 反向）；
- **我的合集（4.8.5「我的分类」→ 4.8.7 改名）**：左栏在颜色分组之后：未分类合集 /
  用户自选合集（带计数）/「＋ 新建分类合集」；`data-filter` 依次为
  `all / pinned / today / c0 / c2 / c1 / uncategorized / cat:<分类名>`（4.8.7 去掉了 `week / older / gray`）。
  右键卡片「分类：<当前分类> › 未分类 / 用户分类」可随时手动归类，手动选择优先于自动归档；
- **自动归档（4.8.5）**：`noteLastActive = max(notesLastOpened[id], modified, created)`，超过 15 天
  （`STALE_DAYS = 15`）没有活动的笔记若**没有手动分类且未置顶**，自动打上 `category = "灰度提示词"`；
  打开 / 编辑 / 置顶后自动清空该字段回到「未分类」。归档在启动、打开管理台、每次切换笔记、
  以及每 30 分钟定时各跑一次；置顶笔记永不自动归档；
- 排序：置顶在最前，其余按「最近打开」（`notesLastOpened`，与侧栏同源），无记录退回修改时间倒序；
- 搜索：标题 + 正文纯文本（含引用块原文），大小写不敏感，130ms 防抖；卡片上只高亮标题命中；
- 键盘：`↑↓` 按**当前列数**跳一行、`←→` 单格、`Enter` 打开、`Delete` 删除（带确认）、
  `/` 聚焦搜索、`Esc`（先清搜索再收起）、`Ctrl / Cmd + K` 收起、`Menu / Shift + F10` 打开卡片菜单；
  焦点在搜索框里时也能用 `↑↓` 选卡片、`Enter` 打开（`←→` / `Delete` 仍留给输入框编辑）；
- 打开一篇笔记：选中该笔记 → 管理台缩回侧栏（300ms）→ 编辑区按原有 180ms 淡出 / 300ms 淡入切换内容；
- 红线：管理台**不得**再长出中栏列表 / 右栏详情 / 批量操作条 / 排序下拉 / 存储细条；
  分类导航可以保留，但右侧必须是同一套卡片，不另造一套「管理专用行」；也不得把 42px 顶栏里的
  头像 / 窗口按钮藏起来或让管理台出现第二条顶栏。

### 24.6 置顶（`pinned`）

- 字段：`Note.pinned: boolean`，`#[serde(default)]` —— 旧数据 / C++ 版没有这个字段时按 `false` 读，
  写回后其他版本会忽略它，**双向兼容**；
- 排序：右侧笔记侧栏把置顶的排最前，其余按「最近打开」（无记录退回 `modified` 倒序）；
  文件管理台同样置顶在前，其余也按「最近打开」（与侧栏一致）；
- 入口：笔记侧栏卡片悬停「置顶」/ 卡片右键菜单；文件管理台卡片悬停 / 右键菜单；
- 红线：置顶只是排序偏好，**不得改 `modified`**（否则会把用户笔记的修改时间搅乱）。

### 25.2 一次更新的完整链路

| 步骤 | 执行者 | 实现要点 |
|---|---|---|
| ① 查清单 | 前端 | `GET <更新源>/latest.json`（`cache: no-store` + 时间戳防缓存） |
| ② 比版本 | `src/services/updater.ts` | `isNewer(清单版本, 当前版本)`；相等或更低 → 静默、不打扰 |
| ③ 下载 | 前端 | `fetch` + `ReadableStream` 分块读，实时进度（百分比 + 已传 / 总量） |
| ④ 校验 | 前端 | `crypto.subtle.digest('SHA-256')` 比对清单；不符**一律拒绝**并给出期望/实际 |
| ⑤ 落盘 | Rust `save_update_file` | base64 解码 → 先写 `.part` 再改名（断电/崩溃不会留下半个 exe） |
| ⑥ 应用 | Rust `apply_update` | 生成 `apply-update.ps1`（UTF-8 with BOM）→ 拉起 → **确认脚本活了才退出** |
| ⑦ 替换 / 安装 | 更新脚本（PowerShell） | 安装版：静默覆盖安装；便携版：旧 exe 改名留底 + 写入新 exe |
| ⑧ 重启与回报 | 更新脚本 + 下次启动 | 重新启动；下次启动按 `localStorage` 里记下的版本提示「已更新到 x.y.z」 |

下载与校验都在前端完成，所以 **Rust 侧没有引入任何新依赖**（不需要 reqwest，离线也能编译）。

### 25.3 两种应用方式（同一个命令，脚本里两个分支）

| 场景 | 判定 | 做法 | 用户数据 |
|---|---|---|---|
| 安装版 | exe 旁存在 `unins000.exe` | 下载**安装包**，`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS /DIR="<当前安装目录>" /LOG=…` | 安装位置不变；`data\` 因 `uninsneveruninstall` 保留 |
| 便携版 | 其它情况 | 只下载 exe：把正在运行的 exe **改名**留底（Windows 允许改名运行中的 exe），再把新文件复制成原文件名 | exe 旁的 `data\` 不动；旧文件留成 `轻提词.exe.old-<旧版本>` |

两种方式都由脚本**等本进程真正退出**（按 PID 等，最多 60 秒）后再动文件，因此不会撞「文件被占用」。

### 25.4 更新清单（`latest.json`）与更新源

```json
{
  "version": "4.7.1",
  "releasedAt": "2026-10-19",
  "notes": "…… 直接显示在 设置 → 关于 的「软件更新」块里的说明 ……",
  "installer": { "url": "files/轻提词安装包_v4.7.1.exe", "size": 3541573, "sha256": "de14e05d…" },
  "exe":       { "url": "files/轻提词_v4.7.1.exe",     "size": 5692928, "sha256": "96885023…" }
}
```

- 更新源优先级：`localStorage['microprompt.update.base']`（运行期兜底，换镜像 / 内网测试不用重打包）
  → `.env` 的 `VITE_UPDATE_URL` → `<VITE_AI_URL>/updates`（默认：更新包跟 AI 服务放一起）；
- `url` 支持**相对清单所在目录**的写法（推荐：换域名、换目录都不用重发清单）与绝对 `http(s)://`；
  相对地址必须先解析再 `fetch`（原因见 25.6 第 1 条）；
- 服务端 `ai_server.py` 发 `/updates/latest.json` 与 `/updates/files/<文件名>`
  （+ `HEAD` 探活、CORS、文件名白名单、路径穿越拦截；更新包**不校验登录态**，因为更新包本身不敏感）；
- `scripts/make-update-manifest.mjs`：发版时算 size + SHA-256、写清单、把两个产物复制进 `updates/files/`。

### 25.5 安全边界（必须知道）

- 更新源是**明文 HTTP + 裸 IP、产物未签名**：SHA-256 只能防「传输损坏 / 文件被换」，**挡不住中间人**
  （攻击者可以同时改清单和文件）。要真防篡改需 HTTPS + Authenticode 代码签名（尚未做）；
- 哈希不符一律拒绝，而且**不落盘、不执行** —— 更新目录里不会留下任何可执行文件；
- **失败安全**：脚本起不来时 `apply_update` 返回错误并且**不退出程序**，界面把 `apply-update.ps1`
  的路径交给用户手动跑；否则用户会落到「点了重启、程序关了、更新没发生」的最糟状态；
- 排障入口 `%LOCALAPPDATA%\轻提词\update\update.log`：**客户端与脚本写同一个文件**，
  一眼能分出是「脚本没起来」还是「脚本里失败了」。

### 25.6 实现时踩过的坑（改这块之前先看）

1. **相对地址必须解析**：`files/x.exe` 直接丢给 `fetch` 会打到应用自身（`http://tauri.localhost/…`），
   拿到约 400 字节的 `index.html` —— 表现是「下载成功但大小不符」。现在用 `new URL(url, 清单地址)`，
   并且下载完**同时**核对 size 与 SHA-256；
2. **GUI 进程必须把子进程 stdio 指向 null**：`windows` 子系统进程没有有效的标准句柄，
   继承给 `powershell.exe` 会让它在启动阶段就死（脚本一行都不会跑）；
3. **`CREATE_NO_WINDOW` 与 `DETACHED_PROCESS` 不能一起用**：`CreateProcess` 会成功返回、子进程却立刻静默死掉；
   `CREATE_BREAKAWAY_FROM_JOB` 则会被 WebView2 的 Job 拒绝（`os error 5`）。现在只用 `CREATE_NO_WINDOW`，
   并以「脚本写出的、带 run id 的起始日志」作为启动成功的判据（不能依赖返回码）；
4. **更新脚本用 PowerShell 而不是 `.cmd`**：安装目录 / 用户名可能含中文，cmd 按 OEM(GBK) 读脚本会乱码；
   PS 脚本存成 **UTF-8 with BOM**，路径一律单引号内联（`ps_quote`，内部 `'` 翻倍转义）。

### 25.7 实测

| 场景 | 结果 |
|---|---|

| 清单版本更高（限速服务器，4.7.1 真机 CDP 实测） | 按钮 `新版本` → 点击 → `下载 46%`（填充 46%、`disabled`）→ 下载校验完 → `重启更新`（实心主色）；三个状态之间工具栏宽度**始终 202.5px 不变** |

### 26.1 为什么是右侧

- 写作时视线和光标都在编辑区，右侧侧栏与「正文向右延伸」的方向一致，展开时编辑区**向左让位**，不遮挡正在写的字；
- 底部抽屉会盖住正文最后几行，且每次展开都要重新定位；侧栏常驻后，翻笔记变成一次点击，不需要「打开抽屉 → 找卡片 → 再收起」；
- 4.8.0 起**删除**旧「向上展开的气泡卡片抽屉 / NoteCard」，只保留侧栏 + 文件管理台两种入口。

### 26.2 结构

│ 笔记  12    🔍 搜索笔记… /│  ns-head（52px，单行）

### 26.3 卡片墙（为什么 2 列 / 卡片留什么）

- **2 列是 4.8.4 按反馈改的**：用户觉得侧栏占界面比例太多、卡片太矮；于是把侧栏收窄到

- **只留标题 / 时间 / 颜色点**：4.8.3 用户明确要求「不显示正文内容」，4.8.4 保留这个红线；
  标题最多两行、`-webkit-line-clamp: 2`，搜索仍然扫描正文，但卡片上只高亮标题命中，不回显正文；

  两行标题在 11.5px 下仍有 34px 高，可读性优先，不做更小的 9~10px；
- 卡片：白底 `#FFFFFF` + 1px `#E9EDF3` 细描边、圆角 11px、**4.8.5 起最小高度 56px**、内边距 `8px 10px 7px`、
  `gap: 2px`、`overflow: hidden`；标题 `line-height: 1.42`（两行约 60px，单行约 48px），比 4.8.4 的 78px 更矮；
- 当前笔记：主题色 36% 细描边 + 主题色 4.5% → 白的极浅渐变 + 1px 主题色淡环，不加整块底色；
- 置顶：只在标题前一枚金色小图钉（`#C08A2F`），不单独占一个分组；
- 颜色点：5px 圆点放右下角，取笔记颜色（黑 `#2b2b2b` / 红 `#C0392B` / 蓝 `#4A90D9`）；
- 悬停操作（4.8.5 再改）：`.ns-card-acts` 是一个**独立小胶囊**（不是铺满卡片）——绝对定位在卡片
  **右侧、垂直居中**，`right: 7px`（与右边框留 7px 空隙），内含「置顶 / 更多」两枚 22×22 方块（圆角 6px，
  间距 2px，胶囊外圈 2px padding + 1px `#E9EDF3` 描边 + 极淡投影）；默认 `opacity: 0` +
  `translate(6px, -50%)`，悬停 / 聚焦 / 键盘光标时 160ms 淡入滑入、`pointer-events` 同步打开，移开复原（成对）；
  按钮 `stopPropagation`，点按钮不会打开笔记；
- 时间：只给 `HH:mm` / `M/D` / `yy/M/D` 绝对时间，**不出现「今天 / 昨天」**；可在设置里整体关闭（见 26.7）；
- 动画：卡片按序号错峰 12ms 淡入上浮（`ns-card-in` / `--card-i`；只在侧栏刚展开的 620ms 内播放，
  点击打开时不重播）；点击打开时 260ms 轻微回弹（`.is-launching`）；`prefers-reduced-motion` 下全部关闭；
- **4.8.7 不显示「灰度提示词」**：侧栏卡片墙、顶部「最近打开」快捷卡片、搜索、条数统计
  统一过滤 `category === "灰度提示词"` 的笔记（自动归档区只在文件管理台可见，见 26.11）；
  侧栏条数胶囊的 `title` 明确写「灰度提示词只在文件管理台显示」；若当前普通笔记为 0、只剩灰度笔记，
  侧栏显示专用空态（标题「笔记都在「灰度提示词」里」+ 一句解释 + 「打开文件管理台」按钮），
  不再误报「还没有笔记」；
- 排序：置顶在前；其余按「最近打开」——`localStorage.microprompt.notesLastOpened` 记录每篇笔记最后一次打开时间，
  打开侧栏时重排一次，点击当下不跳动；没有记录时退回 `modified` 倒序。

### 26.4 底部悬浮工具栏（与编辑界面工具栏完全一致）

- **共用同一组样式**：`.ns-toolbar` 与 `.editor-toolbar` 写在同一条选择器里 —— 42px 高、`0.875rem` 圆角、
  同一套磨砂渐变底（`rgba(255,255,255,.9)` → `rgba(255,255,255,.62)` + `blur(14px) saturate(1.2)`）、
  同一 1px `rgba(148,163,184,.28)` 描边、同一 `--soft-shadow`、同一 28px 图标按钮 `.tool-btn` 与分隔线 `.tool-vline`；
- **同一条水平线**：两者都 `position:absolute; bottom:19px`，分别相对侧栏面板 / 编辑区列居中
  （编辑区工具栏挂在 `.workspace` 上，侧栏展开时按 `left: calc(50% - var(--notes-sidebar-w)/2)` 对齐到编辑区列），
  所以侧栏展开时，两个工具栏在屏幕同一高度并排出现，像一条「贯穿两个面板」的底栏；
- **宽度自适应**：`width: fit-content`，内边距 8px、按钮间距 **6px（4.8.7 统一，原 2px）** —— 按钮少的侧栏工具栏就短，不拉满侧栏；
  分隔线 `.tool-vline` 是**零宽 + 负 margin** 的元素，1px 线用 `::before` 画在间隔正中，
  所以「按钮—分隔线—按钮」的总空隙与「按钮—按钮」同为 6px（见 19.2）；
- 按钮从左到右：`UpdateButton`（有新版才占位，4.8.7 起不再额外加 4px margin）→ 新建（＋）→ 分隔线 → 管理（文件夹）→ 分隔线 → 收起（›）；
- 点「新建」先弹命名弹窗（`InputDialog`，默认值「新建笔记」并全选），确认后才创建；取消不创建任何笔记；
- 三个动作按钮都是**图标按钮**，不写可见文字；动作名通过 `title` / `aria-label` 暴露，悬停显示系统提示；
- 「管理」打开文件管理台，与 `Ctrl / Cmd + K` 同一入口（详见 24.5）。

### 26.5 交互与快捷键

| 操作 | 结果 |
|---|---|
| 单击卡片 | 打开笔记；>860px 侧栏保持，≤860px 自动收起浮层 |
| 悬停卡片 | 卡片上移 1px；两块与卡片同高的「置顶 / 更多」操作从右侧缓动滑入（280ms），轻盖标题尾部 |
| 右键卡片 | 同一套菜单：在编辑器中打开 / 重命名 / 置顶 / 更改提示词颜色 / 删除 |
| 工具栏「新建」 | 先弹出命名弹窗（默认「新建笔记」）；确认后创建该标题的笔记并选中，取消则什么都不发生；窄窗下先收起侧栏再进编辑器 |
| 命名弹窗 `Enter` / 「确定」 | 用输入框里的名字创建笔记（首尾空白会被去掉，空名字回退「新建笔记」） |
| 命名弹窗 `Esc` / 「取消」 | 关闭弹窗，不创建笔记 |
| 工具栏「管理」 | 打开文件管理台（同 `Ctrl / Cmd + K`） |
| 工具栏「收起」 | 收起侧栏；右下角「展开侧栏」浮钮重新出现 |
| 编辑区工具栏「设置」 | 打开设置面板；侧栏保持当前开合状态，关掉设置后回到原位置 |
| 搜索 | 标题 + 正文纯文本，130ms 防抖；命中片段高亮；搜索时条数显示「命中 / 总数」 |
| `/` | 聚焦搜索框（编辑区内不抢） |
| `↑` / `↓` | 按 2 列跳一行（±2 张卡片），自动滚入可视区 |
| `←` / `→` | 单格移动键盘光标 |
| `Enter` | 打开光标所在笔记 |
| `Delete` | 删除光标所在笔记（确认弹窗） |
| `Menu` / `Shift + F10` | 在光标卡片上弹出同一套菜单（置顶 / 重命名 / 改色 / 删除） |
| `Esc` | 有搜索词先清空 → 再失焦 → 最后收起侧栏（编辑区内不抢 Esc） |
| `Ctrl / Cmd + Shift + B` | 全局开合侧栏；打开后焦点交给卡片墙，可直接方向键 / Esc |

- 删除、重命名、改色都走自绘 `ContextMenu` / `InputDialog` / `ConfirmDialog`，Portal 到 body，避免 zoom 坐标错位；
- 侧栏关闭时容器加 `inert`，内部按钮不进入 Tab 序列；打开时移除；
- 当前笔记变化时，卡片墙在 360ms 内把对应卡片滚到可视区（`block:"nearest"`），不打断用户滚动；
- **最近打开不即时重排**：打开一篇笔记只更新 `notesLastOpened`，不立刻重排；下次展开侧栏时按新顺序排一次，
  避免「点一下卡片自己跑到最前」；搜索切换时用最新顺序重排；
- 首次运行没有 `notesLastOpened` 记录时按 `modified` 倒序；置顶卡片始终在最前。

### 26.6 开合与适配

| 视口 | 形态 | 关键规则 |
|---|---|---|
| `> 860px` | **挤压式**（dock） | `.workspace` 改 grid：`minmax(0,1fr) var(--notes-sidebar-w)`，开合走 340ms `var(--ease-out-cubic)` 过渡；`.ns-panel` 左侧 1px 分界线；格式工具栏（含设置齿轮）按**编辑区**居中（`left: calc(50% - var(--notes-sidebar-w)/2)`）；侧栏展开时右下角浮钮隐藏，侧栏工具栏接管新建 / 管理 / 收起 |
| `≤ 860px` | **浮层式**（overlay） | `.workspace` 改 flex；侧栏 `position:absolute; right:0`，宽 `min(520px, calc(100% - 28px))`，左圆角 18px + 投影；遮罩 `rgba(15,23,42,.16)` + `blur(1.5px)`；点遮罩 / 点卡片都收起 |

- 宽度 `clamp(320px, 34vw, 460px)`：一行 2 张卡片，标题最多两行，最小档也放得下 8~10 个汉字；
  默认 1096 × 696 窗口下面板约 429px，编辑区让位后仍保留可读的正文宽度；
- 默认窗口侧栏宽度从 4.8.3 的约 580px 收窄到约 429px（少占约 150px），也不会再出现「一行 3 张、每张很瘦」的挤压感；
- **侧栏整体让开 42px 顶栏**：`.sb-slot.notes-sidebar { padding-top: 42px }`。顶栏是透明悬浮层
  （`.titlebar` 绝对定位在内容之上），若侧栏从 y=0 起铺，会盖住顶栏中间「笔记名」和最右侧
  「置顶 / 最小化 / 最大化 / 关闭」四个按钮；让开 42px 后窗口按钮永远可见可点；
- **顶栏优先级高于侧栏**：`.titlebar { z-index: 65 }`（侧栏 40、窄窗浮层 60、遮罩 50），
  保证展开 / 收起、宽窗 / 窄窗任何状态下窗口按钮都不被遮挡；
- 宽屏侧栏展开时，顶栏笔记名与格式工具栏一样**按编辑区居中**
  （`.app-root.sidebar-open .titlebar-center { right: var(--notes-sidebar-w) }`，状态类挂在 `.app-root` 上）；
- 窄窗（≤860px）下卡片墙仍固定 2 列，卡片靠两行省略收缩，工具栏宽度自适应、不截断；
- 侧栏开合状态存 `microprompt.notesSidebarOpen`：宽屏首次默认展开，窄窗默认收起，之后记住用户选择；
- 窄窗浮层关闭后 340ms 清空搜索词与键盘光标，避免下次打开还停在上次状态；
- 不用 `position:fixed` 做 dock，避免 zoom 下坐标二次缩放；侧栏始终在 `.workspace` 内。

### 26.9 空态与边界

- 无笔记（4.8.5 重做）：编辑区居中显示「还没有笔记」+ 按侧栏开合区分的引导文案
  （侧栏开：`点右下角笔记栏底部的「＋」，写下第一条`；侧栏关：`先点右下角的「展开笔记栏」，再点底部的「＋」新建`），
  侧栏关时另给「展开笔记栏」主按钮；编辑区右下角有一枚虚线弯曲箭头 `.editor-empty-arrow`（主题色 55%，
  2.8s 轻微浮动）把视线引向新建 / 展开按钮。**不再出现「点击左上角 + 新建」这类过期文案**；
- 搜索无结果：放大镜 +「没有找到相关笔记」+「换个关键词试试，标题和正文都能搜」+「清空搜索」次按钮；
- 标题为空：显示「未命名笔记」；卡片不显示正文，正文为空也没有占位文案（4.8.3 起）；
- 超长标题：最多两行省略，卡片 `title` 属性给「标题 + 完整修改时间」；
- 排序：置顶在前 → `notesLastOpened` 倒序 → `modified` 倒序 → `id` 字典序兜底，保证顺序稳定；
- `prefers-reduced-motion`：宽度、位移、淡入全部关闭，卡片墙仍可用。

### 26.10 红线

- ⛔ 不再恢复底部气泡卡片抽屉；侧栏是唯一「随手翻」列表入口；
- ⛔ 卡片不得再显示正文摘要 / 字数 / 标签等第二层信息（4.8.3 用户明确要求只留标题）；搜索仍扫正文，但只在标题上高亮；
- ⛔ 管理台不得再出现中栏列表 / 右栏详情 / 批量操作条 / 排序下拉 / 存储细条；左侧分类保留，右侧必须是同一套 `NoteCard` 卡片墙；
- ⛔ 不再恢复时间脊 / 墨点 / 今天昨天最近 7 天分组；卡片墙不出现自然日标题；
- ⛔ 侧栏工具栏只放「新建 / 管理 / 收起」（另有可选更新药丸）；「设置」只允许出现在编辑区底部工具栏「回到底部」右侧，
  不得再回侧栏或右下角浮钮；
- ⛔ 侧栏宽度不得超过 `clamp` 上限 `460px`；要加宽必须先重新评估 2 列两行卡片的可读性；
- ⛔ 管理台必须保持整页：不得只铺满工作区而露出首页顶栏标题 / 分界线；顶栏只允许保留头像与窗口按钮；
- ⛔ 卡片悬停操作不得再退回右下角小胶囊，也不得再退回 4.8.4 的「两块与卡片同高、铺满右侧」的滑入块：
  4.8.5 的定稿是**右侧垂直居中的小胶囊、与右边框留 7px 空隙**；
- ⛔ 分类相关：自动归档只允许处理「没有手动分类且未置顶」的笔记；「灰度提示词」是系统保留名，
  不得让用户创建同名 / 与内部过滤键（all / pinned / uncategorized / gray / today / week / older / c0~c2）同名的分类；
- ⛔ 合集不得做成第二个文件列表：它是文件夹抽屉，点开文件夹后必须复用同一套 `NoteCard` 卡片墙；
- ⛔ 管理台的展开 / 收起不得再使用整层 opacity 淡入、`width` 动画或纯白背景（会闪白 / 挤压内容），
  必须是 clip-path 揭示 + 与侧栏一致的渐变底；
- ⛔ 删除必须二次确认，不允许卡片内一键直删；
- ⛔ 唯一滚动区只能是 `.ns-grid`，不得让整个面板一起滚；
- ⛔ 不在每次输入时重建所有卡片；`NoteCard` 必须 `memo`（4.8.3 起卡片只依赖标题 / 时间 / 颜色 / 置顶 / 选中态，不计算摘要）；
- ⛔ 不引入图片 / 大插画 / 多色彩虹标签，保持「白纸 + 小卡片 + 一个颜色点」的克制。

### 26.11 分类 · 合集 · 自动归档（4.8.5 新增）

> 用户 4.8.5 反馈的三件事：①「分类要能自己选，软件也要按活跃度自动分类」；②「管理台左侧在置顶 / 全部
> 之上加一个『合集』，点开是手机应用抽屉式的文件夹总览，点进某个文件夹就是现在的全部笔记卡片墙」。
> 这一节是这套功能的设计基线。

**数据模型**

- `Note.category?: string`：缺省 / 空串 = 未分类；用户自选分类与系统自动分类都写这一个字段；
  由 Rust 侧 `#[serde(default)]` 兼容（旧数据无此字段 = 未分类，写回后旧版本会忽略）；
- 分类名规范化：折叠连续空格、首尾 trim、最长 20 字；空名 / 「灰度提示词」/ 内部过滤键
  （`all / pinned / uncategorized / gray / today / week / older / c0~c2`）不允许创建；
- 用户分类列表存 `localStorage.microprompt.noteCategories`（`string[]`），与笔记里的字段互为补充：
  列表决定「合集里出现哪些空文件夹」，字段决定「笔记属于哪个分类」；
- 活跃度：`noteLastActive(note) = max(notesLastOpened[id] ?? 0, modified, created)`；
  `STALE_DAYS = 15`，`isStaleNote()` 计算是否超过 15 天。

**自动归档规则（store 的 `refreshAutoCategories()`）**

- 只处理「没有 `category` 且没有置顶」的笔记 → 打上 `category = "灰度提示词"`；
- 已经有手动分类的笔记永不被自动改写（保留用户选择优先）；
- 灰度笔记被打开 / 编辑 / 置顶后，自动清空 `category` 回到「未分类」（打开笔记时 `select()` 会
  `markNoteOpened(id)` 再刷新，所以「打开即移回」是同一次状态更新，不会闪一下）；
- 触发时机：`init()` 加载完成后、打开管理台时、每次 `select()` 切换笔记时、以及 App 每 30 分钟定时一次；
- 红线：自动归档不得动 `modified` / `created`，只改 `category`；手动选择永远优先。

**管理台 UI**

| 位置 | 规范 |
|---|---|
| 合集入口 | `.fm-rail-collections`，左栏最上方、在「全部笔记」分组之前；主题色淡底 + 虚线四宫格图标 + `›`，明显比普通项突出（这是新增的「第 0 层」入口） |
| 合集总览 | `.fm-collections`：文件夹网格 `repeat(auto-fill, minmax(132px,1fr))`、间距 12~14px；每张 `.fm-folder` = 文件夹图标 + 名称 + 条数，灰度额外「自动」药丸；末尾「＋ 新建分类」卡；点击卡片轻抬 1px |
| 进入文件夹 | 直接复用现有卡片墙（`NoteCard` / 搜索 / 键盘 / 右键 / FLIP 全部不变），只把过滤条件切到该分类；头部 `‹ 合集`（`.fm-back`）返回 |
| 我的合集 | 4.8.7 起左栏颜色分组之后是三组中的最后一组「我的合集」：未分类合集 / 各用户合集 / ＋新建分类合集；每项带实时计数。4.8.5 的「我的分类」与左栏「灰度提示词」入口已移除 —— 灰度只在「合集」抽屉里有一个文件夹（`data-filter` 为 `uncategorized / cat:<名>`，`all / pinned / today / c0 / c2 / c1` 在固定组里） |
| 手动归类 | 卡片右键菜单「分类：<当前分类> › 未分类 / 各用户分类」，当前项打勾（`.ctx-check`）；按钮为二级菜单，不新增主菜单层级 |
| 新建分类 | 合集里：确认后留在合集并高亮新文件夹（1.7s `.is-fresh`），方便连续建多个；左栏里：确认后直接进入该分类 |
| 动画 | 进入文件夹 / 返回合集成对（260 / 240ms OutCubic）；卡片墙切换加 `.is-cat-in` 淡入上浮；`prefers-reduced-motion` 全关 |
| 文案 | 空分类给引导（「灰度提示词还是空的 / 超过 15 天没有打开的笔记会自动移进来」等），不出现「暂无内容」这种冷文案 |

**红线**

- 合集必须是文件夹抽屉，点开后就是同一套卡片墙，**不得**做成第二个文件列表 / 树形目录 / 中栏详情；
- 自动归档只允许处理未分类且未置顶的笔记；「灰度提示词」不可被用户创建 / 改名 / 删除；
- 分类删除、改名 UI 暂不提供（`removeNoteCategory()` 已在 store 里预留），要加必须先补本规范；
- 合集里必须有「全部笔记 / 置顶 / 未分类 / 灰度提示词」四个固定文件夹，用户分类追加在后；
- **4.8.7：灰度提示词的唯一入口是「合集」抽屉里的那个文件夹** —— 侧栏笔记本列表（卡片墙 / 最近打开 /
  搜索 / 计数）不显示灰度笔记，管理台左栏也不再有灰度入口；不得为了「好找」再把灰度塞回侧栏或左栏。
