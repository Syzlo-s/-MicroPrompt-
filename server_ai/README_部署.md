## 二、部署（覆盖更新，约 1 分钟）

```bash
# 1) 上传新文件（在本机执行；路径按你的实际情况）
scp server_ai/ai_server.py server_ai/admin_cli.py server_ai/selfcheck.py \
    root@<服务器IP>:/home/admin/ai_server/

# 2) 登录服务器
ssh root@<服务器IP>
cd /home/admin/ai_server

# 3) 先设好两个密钥（缺 MP_DEEPSEEK_KEY 会直接启动失败；MP_ADMIN_KEY 留空则自动生成）
pkill -f ai_server.py
MP_DEEPSEEK_KEY='sk-你的DeepSeekKey' MP_ADMIN_KEY='你自己设一个长密钥' \
  nohup python3 ai_server.py > ai_server.log 2>&1 &

# 4) 看日志确认启动
tail -n 20 ai_server.log

# 5) 自检：确认新代码生效（关键一步）
MP_ADMIN_KEY='你自己设一个长密钥' python3 selfcheck.py
```

> 启动失败排查：日志里出现「启动失败：未设置 MP_DEEPSEEK_KEY 环境变量」，
> 就是第 3 步漏了 `MP_DEEPSEEK_KEY`（4.0.2 起源码里不再内置 Key）。

自检输出应该是 10 项全 `[OK]`；如果提示
「`/ai/health 不存在（http=501）`」，说明服务器上跑的还是 4.0.0 旧代码，
重新上传 `ai_server.py` 并重启即可。

### 端口与防火墙
- 仍然是 **2581/TCP**（服务器 firewalld + 阿里云安全组已放行，无需改动）。
- **2580/TCP 也要放行**：4.1.0 起它由 `ai_server.py` 自己监听（接管原先 Casdoor 的地址），
  客户端里 `VITE_CASDOOR_URL` 写死的就是这个端口。
- `MP_AUTH_MODE=casdoor`（默认）时服务端要能访问 **127.0.0.1:2580**（本机 Casdoor）来校验登录凭证；
  如果 Casdoor 不在本机，用 `MP_CASDOOR_URL=http://<服务器IP>:2580` 指定。
  `MP_AUTH_MODE=builtin` 时不再需要访问任何外部账号服务。

### 两个已知坑（本版已处理 / 需注意）
1. **旧版是单线程**：`HTTPServer` 一次只能处理一个请求，一个慢的 DeepSeek 调用
   会把后面所有请求（包括浏览器预检）堵到超时，客户端表现为「AI 服务超时或无法连接」。
   4.0.2 已改为多线程（并且在 Python 3.6 上也能用）。
2. **管理员密钥建议只用字母数字**：不同终端传参编码不一致时，含中文的密钥会导致
   `admin_cli.py` 认证失败（服务端已做兼容处理不会崩，但会认不出来）。

## 二·二、在线升级（4.7.0：软件内直接升级）

客户端启动会静默查一次 `<更新源>/updates/latest.json`（设置 → 关于里也能手动查）。
更新源默认就是本服务 `http://<服务器>:2581/updates`，本服务负责发两样东西：

| 路由 | 作用 |
|---|---|
| `GET /updates/latest.json` | 最新版本清单（版本号 / 更新说明 / 两个下载项各自的 size 与 sha256） |
| `GET /updates/files/<文件名>` | 安装包或便携版 exe（分块发送，256 KB 一块；支持 `curl -I` 探活） |
| `GET /updates/` | 返回一行用法提示，方便浏览器随手验证 |

**目录长这样**（由 `scripts/make-update-manifest.mjs` 生成，整目录 scp 上来即可）：

```
server_ai/updates/
├── latest.json                        # 清单（小、文本、可以进版本库）
└── files/
    ├── 轻提词安装包_v4.7.0.exe          # 安装版走这个（静默覆盖装，更新快捷方式/注册表）
    └── 轻提词_v4.7.0.exe                # 便携版走这个（换 exe，旧文件留 .old-<版本>）
```

**发版当天怎么操作**

```bash
# 本机：生成清单 + 复制产物（会打印 size 与 sha256）
node scripts/make-update-manifest.mjs --notes-file release/notes-4.7.0.md
# 上传（整个目录，含 files/）
scp -r server_ai/updates root@8.163.51.216:/home/admin/ai_server/
# 服务器：确认能取到（不需要登录）
curl -s http://127.0.0.1:2581/updates/latest.json
curl -sI http://127.0.0.1:2581/updates/files/轻提词安装包_v4.7.0.exe
```

**注意**

- **更新包不校验登录态**（谁都能下载更新包，这没问题）；文件名做了白名单，`..`、子目录、
  隐藏文件一律拒绝，路径穿越已挡。
- **清单别放进 CDN 长缓存**：`latest.json` 响应头是 `no-cache`（现取现发），
  文件本身 `max-age=300`。若前面挂了 Nginx/CDN，记得让 `latest.json` 不缓存，否则发新版不生效。
- **必须允许跨域**：客户端页面源是 `http://tauri.localhost`，本服务的 `/updates` 已带
  `Access-Control-Allow-Origin: *`。换成别的静态服务器发更新包时，同样要带 CORS 头。
- **明文 HTTP + 未签名**：SHA-256 只能防传输损坏/文件被换，**挡不住中间人**。
  后续建议上 HTTPS（域名 + 证书）并给 exe 做代码签名。
- 上传新包后不用重启服务（每次请求现读文件），但 `MP_UPDATES_DIR` 放错位置时
  启动横幅里的「在线升级」一行会显示「未放置 latest.json」，照它排查即可。

## 三、额度规则（服务端唯一判定，改客户端绕不过）

| 用户 | 规则 |
|---|---|
| 未付费 | 每天 **3 次**（北京时间 0 点重置），超出返回 `402 free_exhausted` |
| 会员 | 正常使用不限量，但设 **300 次/天** 防滥用上限（超出返回 `402 member_cap`） |
| 免费不限量 | 你在后台按账号开通（`/admin` → 用户与 AI 额度）；不受每天 3 次限制，仍保留 2 秒最小调用间隔 |
| 所有人 | 两次调用最小间隔 2 秒（返回 `429 rate_limited`）；单次文本上限 2 万字符 |
| 身份 | 必须带登录 `access_token`（`casdoor` 模式由 Casdoor 校验，`builtin` 模式由本服务自签自校验），校验失败返回 `401 auth` |
| 已停用账号 | `builtin` 模式下即使密码正确也拒绝登录（`该账号已被停用，请联系客服`）；已签发的旧令牌立刻失效 |

> 说明：AI 只对**云端账号**开放。
> **4.0.3 起客户端已彻底移除「本机离线账号」**：注册 / 登录一律走云端账号，
> 旧的 `local:*` / `local-admin` 登录态在启动时会被清除并要求重新登录，
> 因此不会再出现「下载软件后提示本机离线账号、AI 润色用不了」的情况。

## 二·五、自建账号体系（4.1.0；4.1.1 修注册）

> **4.1.1 变更**：用户名放开**中文**（1-32 位，中英文/数字/`_`/`-`，首尾不能是 `_` 或 `-`；
> 单字用户名也允许，例如「吴」）；报错改成整句「用户名不符合要求：…」/「密码不符合要求：至少 8 位」；
> 客户端注册页同步显示规则。老客户端（4.0.3）不升级也能用中文名注册——规则是在服务端放开的。

`MP_AUTH_MODE=builtin` 后，账号相关请求全部由 `ai_server.py` 在 **2580** 端口处理
（`MP_AUTH_PORT` 可改，`0` 表示不监听）。客户端一行都不用改：它只调下面 5 个接口。

| 接口 | 客户端用途 | 关键约定 |
|---|---|---|
| `POST /api/signup` | 注册 | JSON 请求体；用户名 **1-32 位**、可用**中英文/数字/`_`/`-`**（首尾不能是 `_` 或 `-`）；密码 ≥8 位（4.1.1 起放开中文与单字用户名） |
| `POST /api/login/oauth/access_token` | 登录 | `application/x-www-form-urlencoded`；返回 `{access_token, expires_in, token_type}` |
| `GET /api/get-account` | 读资料 | `Authorization: Bearer <token>`；**只返回** `id/name/displayName/avatar/createdTime/lastLoginTime` |
| `POST /api/update-user` | 改昵称/头像 | 忽略请求体里的 `id/name/pwd/tokenVer/status/note`（客户端改不了自己的身份与状态） |
| `POST /api/change-password` | **自己改密码（4.1.8）** | 必须带令牌 + **必须验原密码**；新密码 8~128 位且不能与原密码相同；成功后 `tokenVer +1`（其它设备掉线）并返回**新令牌**给当前设备 |
| `POST /api/upload-resource` | 上传头像 | multipart；按**文件头魔数**判类型、≤2 MB、服务端生成文件名 |

- **令牌**：HS256 自签 JWT，payload 含 `id` / `name` / `ver` / `exp`，
  密钥在 `data/jwt_secret.txt`（600 权限，首次启动自动生成，**与管理员密钥分开**）。
- **密码**：`pbkdf2_sha256$迭代数$盐$哈希`；比对用 `hmac.compare_digest`，
  失败话术统一为「用户名或密码不正确」（不暴露账号是否存在），登录失败一样计入限速。
- **旧令牌失效**：改密 / 停用 / 踢下线都会让该账号 `tokenVer +1`，
  旧令牌即使没过期也会被判 `401`（客户端表现为要求重新登录）。
- **错误话术**（客户端会直接显示）：`用户名或密码不正确` / `该账号已被停用，请联系客服` /
  `尝试次数过多，请 10 分钟后再试` / `用户名已被注册` / `请求格式不正确`。
- **未知的 `/api/*`、`/avatar/*`** 一律 404 JSON；所有响应都带
  `Access-Control-Allow-Origin: *`，`OPTIONS` 预检返回 204 —— 否则 WebView2 会把它当网络故障。

### 用户自己改密码（4.1.8）

以前客户端「用户」页写的是「如需修改密码，请联系客服」——用户只能发邮件，你只能手动
`/ai/admin/account/resetpwd` 生成临时密码再发回去。4.1.8 起客户端可以自己改，服务端只管校验：

| 规则 | 为什么这么定 |
|---|---|
| 必须带登录令牌，**身份只从令牌取** | 不接受客户端传 `uid` / `username`，否则就是「拿自己的令牌改别人的密码」 |
| **必须验原密码** | 手机 / 电脑被同事临时借用时，不能直接就把密码改掉 |
| 新密码 8~128 位、不能与原密码相同 | 与注册同一套规则，避免「改了个更弱的」 |
| 失败话术统一（`原密码不正确`，不区分账号是否存在） | 与登录一致的账号枚举防护 |
| 成功后 `tokenVer +1` | 其它设备上的旧令牌立刻失效（等于顺手踢下线） |
| **同时返回一张新令牌** | 当前设备用新令牌继续用，**改完不用重新登录**（客户端会把旧令牌换掉） |

改完的行为，客户端会明确告诉用户：**「其它设备上的登录已失效，本机继续保持登录」**。

上线后可以这样验（不会动任何真实账号）：

```bash
# 1) 不带令牌 → 401（说明接口在，不是 404）
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:2580/api/change-password \
  -H 'Content-Type: application/json' -d '{"oldPassword":"x","newPassword":"yyyyyyyy"}'
# 期望 401

# 2) 本地联调实例上跑完整回归（含改密 11 项）
python3 tests/test_accounts.py
```

> 提醒：改密接口和登录一样走 **http 明文**（2580）。要真正安全得配 HTTPS（Caddy + 域名）
> 或让用户走 `ssh -L 2580:127.0.0.1:2580 admin@<服务器>`，这一条在「已知限制」里一直挂着。

### 回退到 Casdoor（开关）
```
# 1) 打开 /home/admin/ai_server/run.env，删掉 MP_AUTH_MODE=builtin（或改成 casdoor）
# 2) 重启 AI 服务：./start.sh
# 3) 重新起 Casdoor：cd /home/admin/casdoor && nohup ./casdoor > casdoor.log 2>&1 &
```

### 用户下单 → 你确认开通 的完整流程

1. 用户在软件里：设置 → AI 助手 → 开通会员 → 选日卡/月卡 → 得到订单号，扫码付款；

**方式 A（推荐，手机也能用）：后台页面**

浏览器打开 `http://<服务器IP>:2581/admin`

1. 粘贴管理员密钥 → 点「保存到本浏览器」（密钥只存在你自己浏览器里，不会写进页面）；
2. 订单列表里点「确认收款并开通」即可，支持勾选「每 15 秒自动刷新」；
3. 顶部有运营摘要：**待处理 N 笔 / 今日已开通 N 笔 · ￥X / 累计已开通 N 笔 · ￥X**；
4. 同一页面还能「加天数」和「查用户额度」；
5. **「用户与 AI 额度」面板（4.0.3 新增）**：列出所有登录过软件的账号 ——
   用户名、首次 / 最近登录时间、今日用量（免费 / 会员 / 不限量）、累计调用次数、会员到期；
   每行可以「重置今日」「清零累计」，或者一键**开通免费不限量**（再点一次即取消）；
   面板顶部有「账号数 / 今日登录 / 免费账号数 / 今日总调用」摘要，并支持按用户名搜索；
6. **账号管理（4.1.0 新增，`builtin` 模式下才有按钮）**：同一张表里多出
   注册时间 / 最后登录(IP) / 状态 / 备注 几列，以及
   **新建账号**、**重置密码**（弹出一次性临时密码，只显示这一次，转告用户后请其自行修改）、
   **停用 / 启用**（停用后无法登录、旧令牌立刻失效）、**踢下线**（密码不变、强制重登）、
   **备注**（只给自己看，客户端看不到）；
7. 已做手机适配（窄屏下按钮全宽、卡片竖排、表格可横向滑动），随手用手机也能处理订单。

**方式 B（服务器命令行）**

```bash
cd /home/admin/ai_server
python3 admin_cli.py list            # 看所有订单（claimed = 用户说已付）
python3 admin_cli.py confirm 20261010XXXX-AB   # 确认收款 → 自动开通对应天数
```

4. 客户端弹窗会自动轮询到「已开通」，额度立即生效。

**没收到钱怎么办：点「打回（没收到款）」（4.1.3 新增）**

用户点了「我已完成支付」，但你查收款记录发现**这笔钱根本没到**（没备注订单号、截错图、付错金额…），
以前只能让它一直挂在「待处理」里，用户也会一直等。现在订单页那笔订单上多了一个红色
**「打回（没收到款）」**按钮：

1. 点它 → 弹出确认框，可以顺手写一句原因（例如「收款码没备注订单号」，会写进操作日志）；
2. 确认后该订单立刻变成 `canceled`（页面显示「已作废」，卡片上带作废时间与原因）；
3. **不会开通会员、不计收入**；用户端弹窗会显示「这笔订单已被作废」，并可点「重新选套餐」再下一单；
4. 已开通（`paid`）的订单**不允许打回**（接口返回 400 `not_rejectable`）——
   会员天数已经加上去了，要退得走「手工加天数 / 停用」那条路，避免一键把会员抹掉。

> 命令行也能做同样的事（服务器上）：
> `curl -s -X POST http://127.0.0.1:2581/ai/admin/reject -H "X-Admin-Key: $(python3 admin_cli.py key)" -H 'Content-Type: application/json' -d '{"id":"订单号","reason":"没收到款"}'`

> 用户中途关掉弹窗再打开，会自动回到原来那笔订单（等待确认 / 继续付款），
> 不会再生成第二笔，也不用担心他重复付钱。
> 同一笔订单你手滑点两次 `confirm` 也只加一次会员天数。

### 配色规则（4.1.4 起，改界面前先看这条）

### 类名规则（4.1.5 起，改布局前先看这条）

左侧导航占用了 `.side`（`width:236px / height:100vh / position:sticky`），
**内容区不要再拿 `side` 当修饰类**：4.1.2~4.1.4 的概览页写的是 `<div class="grid side">`，
它同时命中了左侧栏的 `.side`，于是「近 14 天趋势图 + 额度分布」两张卡片被压成 236px 宽的

图表恢复 **723px** 宽；`admin_panel_smoke.mjs` 会卡「行宽 ≥ 内容区 98%、每栏 ≥ 25%、图宽 ≥ 500px」。

### 后台偶发空白怎么办（4.1.6 / 4.1.7，运维最常问的一条）

**现象**：后台偶尔整块空白——概览页 4 张 KPI 卡片和图表都不出来，只弹一句「无法连接服务」；
浏览器控制台报 `net::ERR_CONTENT_LENGTH_MISMATCH`（响应被截断）。刷新一下又好了。

**原因**（实测结论，不是猜的）：

1. 本服务是 **HTTP/1.0 短连接**（`BaseHTTPRequestHandler` 默认），响应头里原来没有
   `Connection` 头，浏览器/中间代理会误以为能复用连接 → 4.1.6 起统一补
   `Connection: close`（`end_headers()` 一处生效）。
2. 真正常见的原因是**本机代理**：如果 Windows 开了系统代理（例如抓包/科学上网工具占着
   `localhost:<端口>`），Chrome 会走它，而它转发 HTTP/1.0 响应时会偶发截断。
   实测（headless Chrome 连线上后台，每次加载都会请求概览接口）：

   | 走法 | 概览/轮询请求失败率 |
   |---|---|
   | 走本机系统代理 | **10 / 14 次失败** |
   | 绕过代理（`--no-proxy-server`） | **0 / 28 次失败** |

   同一台服务器用 curl / Node 直连 90 次全部成功 → 服务端没问题，是代理那一跳的问题。
3. 4.1.7 起后台自己兜住这件事：**读接口**（`need()`：概览/用户/订单/日志/安全/收款码）
   在网络层失败时**自动重试一次**（紧接着重发必成功），失败时页面给出可读提示、旧数据继续显示，
   不再留一整块空白。**写接口**（确认收款/打回/重置/加天数）**绝不自动重试**，
   避免「第一次其实成功了、重发又执行一遍」。

**想彻底不看见这个报错**：把服务器 IP 加进代理的直连/绕过列表，或临时关掉系统代理
（Windows：设置 → 网络和 Internet → 代理）。这不影响服务端，纯浏览器侧的一跳。

### 实时是怎么做的（为什么不用 SSE / WebSocket）

- 服务端每次数据落盘时把内存里的修订号 `rev` +1（`stats.json` / `admin_log.json` / `auth_guard.json`
  这三个高频写的文件豁免，避免刷屏）；
- 页面每 2 秒 `POST /ai/admin/poll` 拉一次轻量快照，**`rev` 没变就直接返回、不重画界面**；
- 页签切到后台（`document.hidden`）时暂停轮询，回来立刻补一次；
- 好处：只用一个普通 HTTP 接口，不用长连接、不用额外依赖，Python 3.6 的
  `ThreadingHTTPServer` 扛得住；实测从「客户端下单」到「后台徽标变 1」在 2 秒内。

## 五、以后接在线支付通道（自动开通）

代码里已经留好位置，只要在 `ai_server.py` 的 `_do_pay_notify()` 里补三件事：

1. 按通道要求验签（虎皮椒 / 易支付 / 微信支付 V3 / 支付宝 各有自己的验签方式）；
2. 从回调里取出订单号，找到 `store.get_order(orderId)`；
3. 调用 `store.confirm_order(orderId)` —— 它会把订单标记 `paid` 并给用户加会员天数。

然后把回调地址填成 `http://<服务器IP>:2581/ai/pay/notify` 即可。
（现在该接口返回 `501 pay_channel_off`，避免被误调用。）

## 六、数据文件与备份

`data/` 目录：

| 文件 | 内容 |
|---|---|
| `users.json` | 见过的用户（id / 用户名 / 首末次时间） |
| `members.json` | 会员到期时间 |
| `free.json` | 管理员开通的「免费不限量」账号（4.0.3 新增） |
| `usage.json` | 每人每天的免费 / 会员 / 不限量用量 |
| `orders.json` | 订单记录 |
| `accounts.json` | **账号表**（4.1.0 新增）：用户名 / 显示名 / 头像 / 密码哈希 / 状态 / 备注 / `tokenVer` |
| `auth_guard.json` | 登录失败计数与锁定状态（4.1.0 新增，可随时删，删掉等于解锁所有人） |
| `jwt_secret.txt` | 自令牌签名密钥（4.1.0 新增，600 权限；**删掉会让所有人令牌失效**，需重新登录） |
| `admin_key.txt` | 管理员密钥 |
| `paycode.png` | 收款码（可选） |
| `backup/` | **自动备份**（见下） |

> 账号表里的 `id` 是 UUID，**永远不要假设它等于用户名**：
> `free.json` / `usage.json` / `members.json` 都按这个 id 记录额度，
> 换用户名不影响额度，换 id 会（4.1.0 上线时特意复用了 Casdoor 时期的 id，所以老额度都还在）。

### 自动备份（4.0.2 新增）

每次**启动服务**时，会把上面 6 个 json（users / members / free / usage / orders / accounts）复制到 `data/backup/`，
命名为 `members.20261010-093501.json` 这样的时间戳文件，**每个文件只保留最近 7 份**，
启动日志里会打印「已备份 N 个数据文件」。

**数据文件损坏会自动恢复**：启动时若某个 json 读不出来（磁盘写坏、被手工改错等），
服务会从 `backup/` 里挑**最新一份能解析的备份**恢复，并把损坏的原文件留档为
`xxx.json.corrupt`，日志里会写明「数据文件损坏 → 使用备份文件 → 已从备份恢复」。
（实测：把 `members.json` 写坏后重启，用户会员到期时间原样恢复。）

> 为什么要这个：`members.json` / `orders.json` 丢了就等于用户白付了钱。
> 想手工再兜一层可以偶尔执行：
> ```bash
> tar czf ~/ai_data_$(date +%F).tar.gz -C /home/admin/ai_server data
> ```
> 注意：备份只在**启动时**做，所以服务长期不重启时，建议按上面这条定时打包一次。

```bash
# 备份
tar czf ~/ai_data_$(date +%F).tar.gz -C /home/admin/ai_server data
```

写入方式：先写 `.tmp` 再改名覆盖，不会写坏；单进程单锁，不会并发写乱。

## 八、排查

| 现象 | 原因 / 处理 |
|---|---|
| 客户端提示「登录状态已失效」 | token 过期（7 天）→ 重新登录；或服务重启后 `data/jwt_secret.txt` 丢了；或该账号被改密/停用/踢下线（`tokenVer` 变了） |
| 客户端提示「无法连接 AI 服务」 | 2581 未启动 / 安全组关闭 → `tail -n 50 ai_server.log` |
| 客户端提示「无法连接服务器」（登录/注册时） | 2580 没在监听：确认 `run.env` 里有 `MP_AUTH_MODE=builtin`，再看启动日志那两行「账号模式 / 账号服务」 |
| 登录一直提示「用户名或密码不正确」 | 密码确实错了；或该 IP 触发限速（`auth_guard.json`，删掉即清零）；或账号是 `casdoor` 模式建的、`accounts.json` 里没有 |
| 所有人都是 402 | 免费次数用完是正常的；要改次数用 `MP_FREE_DAILY` |
| 想把账号体系退回 Casdoor | 见「二·五」结尾的回退开关（代价：所有人重新登录一次） |
| 管理命令报「无法连接服务」 | 服务没起来，或 `MP_URL` 端口不对（默认 2581） |
| 用户说付了钱但没开通 | `python3 admin_cli.py list` 看有没有 `claimed` 订单，然后 `confirm` |
